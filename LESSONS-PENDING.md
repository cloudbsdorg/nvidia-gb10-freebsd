- [replayed to Honcho 2026-11-21 by the orchestrator] 2026-11-20 nvidia-prime-import (fix round after the Opus review): (1) a stock RM teardown (os_unlock_user_pages) does vm_page_dirty() on every page of a writable descriptor, and vm_page_dirty() KASSERTs all-valid; noobj pages from linuxkpi are never valid, so importing another driver's pages panics an INVARIANTS kernel at the first close unless the dirty step is guarded at the dirty site (busied, vm_page_all_valid). (2) linuxkpi's user-mmap fault (lkpi_vmf_insert_pfn_prot_locked) inserts any PHYS_TO_VM_PAGE page into its object and validates it, ignoring the wire count, so an imported wired page can legitimately gain an object: busy + re-check + wire in one module, never check in one module and wire in another. (3) Imported pages need a reference on the exporter's dma-buf for the whole handle life, dropped last, or the exporter's pool reuses them. (4) A KAPI table that grows needs a kld version bump (MODULE_VERSION / MODULE_DEPEND) and a layout tag in the version string compared before any member write. (5) `sed` with a greedy `.*` over a 140 KB single line is quadratic and a killed test script runs its EXIT trap (rm -rf TMPD): use grep -o. (6) Keep new BSD logic out of NVIDIA's proprietary files; they should only call into our file.
